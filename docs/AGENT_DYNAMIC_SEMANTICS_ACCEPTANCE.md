# Agent 动态理解与餐食引用链路修复

日期：2026-10-14。本轮基于现有 Agent 增量修改；未更换框架，未重建 API、数据库或前端聊天流程。

## 实际问题

真实对话中，用户已记录午饭，再说“晚饭是把虾仁滑蛋换成了炒空心菜，其他一样”。
原意图模型提取了 dinner 和 replace_item，却把任务分类为更正已保存午饭并绑定原午饭 ID。
原确定性执行分支只处理份量，忽略换菜参数，返回“请说明要修改哪项食物，以及改成多少克”。
该失败轮仅执行读取，没有写入或生成晚饭草稿。

## 本轮改动

- `agents/intent_router.py`：普通业务、营养反馈、日期、个人查询和知识问答统一进入现有结构化语义模型。
  保留简单寒暄快捷路径；日期和营养等辅助识别函数不再直接替业务请求选任务。
  给模型提供请求时区下的今天/昨天/前天日期，避免有明确时钟还反复询问日期。
  增加计划冲突检查：新记餐错误绑定旧写入目标、目标餐次/日期冲突、饮食混入训练字段时，
  向现有模型提供冲突事实，最多复核一次；仍有冲突则停止，不执行业务修改。
  复核若产生记忆操作，仍经过原有记忆语义复核和当前输入证据校验。
- `schemas/agent_task.py`、`services/agent_task_state.py`、`services/agent_context_builder.py`：
  在现有 JSON Task State 增加 `reference_entities`，与实际修改目标 `entities` 分开。
  新任务不继承旧餐的目标和整餐营养上限；参考 ID 校验、跨轮保存、上下文预算优先级均已补齐。
  旧任务数据缺少新字段时使用空默认值，无须数据库迁移。
- `services/agent_planning.py`：保留完整参数短答、明确生命周期指令和明确候选序号的确定性处理。
  复杂表达与候选歧义交给语义模型；通用删除指代有多个候选时，保留原任务和候选列表，不允许模型猜选。
  对已理解的已有对象修改，仍可用确定性候选解析补入真实项目索引；不会把这些写入目标带入新记餐。
- `services/agent_handlers/task_action.py`、`general.py`、`agents/prompts.py`：
  工具模型收到当前结构化行动计划。确定性份量编辑只处理份量操作，其他修改交回工具模型。
  换菜即使同时给出克数，也不会被降级成修改原食物克数。真实选择歧义和非法参数继续阻断执行。
- `agents/tools/nutrition.py`、`registry.py`、`runtime.py`、`factory.py`：
  新增 `propose_nutrition_entry_from_reference`，复用现有 NutritionService、确认、工具日志和幂等机制。
  按真实来源 ID 和版本检查，只传需要替换的项目；程序复制未提及食物的已保存份量与营养依据。
  新日期、餐次由当前请求决定，原餐不变。参考 ID 与计划不符、来源过期、索引错误时不创建草稿。
  当前工具用于复制整餐或替换来源中的项目；没有把任意业务行为自动变成新工具权限。
- `schemas/nutrition.py`、`services/nutrition.py`、`agents/tools/nutrition_changes.py`：
  在原已保存餐食更正操作中增加可选的 `changes[].replacement`，支持确实修改原餐的换菜。
  继续使用 `nutrition_entry_update` 确认操作、版本检查、原 ID 和修订历史。
  替换项按新食物依据计算，未提及食物保留原快照；可继续修订待确认替换项的份量。
- `frontend/.../agent_page.dart`：原更正确认卡展示原食物→新食物、份量和估算依据，仍由用户确认生效。

现有重要写入的草稿、校验、确认机制保留；参考对象不会因此获得修改权限。
没有改为“LLM 随意直接写数据库”，也没有用固定语句匹配替代语义理解。

## App 验收

1. 打开 AI 私人教练，进入已有午饭记录的原对话，发送：
   “晚饭是把虾仁滑蛋换成了炒空心菜，其他一样”。
   预期生成独立晚饭草稿，按常见小碗份量估算新菜；午饭不变，不要求用户自行计算克数或营养。
2. 在该晚饭草稿确认前发送“空心菜其实200克，其他不变”。
   预期修订同一份晚饭草稿，旧卡失效，不另建第二份独立晚饭，不修改午饭。
3. 核对晚饭卡后自行确认，再到饮食页核对：新增晚饭一餐，午饭的食物和份量保持原值。
4. 发送“昨天晚饭也这样吃的，帮我记上”。预期生成昨天晚饭的新草稿，不挪动今天的记录。
5. 发送“先不要保存昨天那份，只看今天已保存的午饭和晚饭，哪个热量低”。
   预期读取记录进行比较，不新增、更正或批准记录，也不把只读咨询当作取消草稿。
6. 若确实要改原午饭，明确发送“今天午饭里的虾仁滑蛋其实是炒空心菜，把午饭原记录改一下，其他不动”。
   预期生成原午饭的换菜更正确认卡，展示旧菜→新菜，不要求把换菜改写成克数修改。

语义模型仍可能判断错误；本轮增加了结构化冲突复核和执行保护，并通过上述实际样本验收，
不代表所有自然语言表达或尚无对应工具的业务都已支持。
