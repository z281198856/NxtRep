# AI 对话历史与归档验收

本轮只调整对话列表、自动标题、归档链路和聊天入口，保留 Agent 理解、工具、确认与任务状态主流程。

## 实现与原因

1. 历史按最近聊天日期分为“今天”“昨天”“YYYY年M月D日”，无消息时使用创建日期。
   使用设备本地日历日期；后端按 `coalesce(last_message_at, created_at)` 排序，改名和归档不会改变聊天日期。
2. 原前端空标题一律显示“训练咨询”，且会直接显示供 Agent 使用的内部滚动摘要。
   现在列表显示内容标题和简洁时间，内部状态摘要保留在 Agent 上下文中。
3. 标题单独使用 `glm-4-flash-250414`，主教练模型不变。模型只读取有限的聊天文字样本，
   最多取开头 6 条和最近 6 条、每条 600 字，不附带照片二进制、资产元数据或内部 Task State。
   标题生成在历史请求的后台阶段进行，不进入 Agent 工具执行链；同时只进行一条模型调用。
   每批最多 8 段，失败冷却 60 秒，格式不合格最多补正一次，整个模型阶段受 8 秒预算约束。
   失败时保留首条消息的简短摘录，之后可重试，不伪装已生成摘要。
4. 新增 `title_source` 和 `title_through_sequence` 两个兼容字段，区分手动命名、生成标题和摘录。
   手动名称不自动覆盖；提交使用版本、原标题和来源条件，生成期间的手动改名优先。
   自动标题在累计 12 条新消息后允许刷新。旧记录保留 legacy 标记，不会因浏览历史而未经授权批量外发。
5. 真实日志显示归档 PATCH 返回 500：SQL UPDATE 后 `updated_at` 未加载，Pydantic 同步序列化触发
   `MissingGreenlet`。为该 ORM 模型开启 eager defaults，在异步写入阶段返回更新时间，修复归档和改名的响应。
6. 历史页就地显示失败原因，保留原条目；防止重复点击和快速切换列表时旧请求覆盖新列表。
   遇到版本冲突，归档/恢复仅重新读取一次，再对同一 ID 更新状态，不覆盖标题。
   已归档列表提供“恢复对话”；恢复后可继续打开原消息。
7. 聊天页提供“新建对话”“历史对话”两个带文字和图标的按钮。手机分两行，宽屏同一行，
   打开历史时收起输入焦点。保留历史与长期记忆两项能力。

数据库迁移：`a9d6e4c1b832_add_conversation_title_metadata.py`，本机已执行。
配置：`NXTREP_CONVERSATION_TITLE_MODEL`、`NXTREP_CONVERSATION_TITLE_TIMEOUT_SECONDS`。

## App 验收步骤

1. 进入“AI私人教练”，检查“新建对话”“历史对话”文字入口。
2. 点“历史对话”，核对今天、昨天、此前日期分组及不同话题的标题；列表不再显示内部任务摘要。
3. 打开一段旧对话，核对消息和已有记录展示仍在。
4. 在历史条目菜单点“归档”，确认出现成功提示、条目移到“已归档”。
5. 在“已归档”的同一条目菜单点“恢复对话”，返回“对话”列表后打开，核对原消息仍在。
6. 新建对话聊一项具体问题，再打开历史；标题生成时可先看到首条消息摘录，后台完成后列表会有限次数自动刷新。
7. 手动重命名后再继续聊天，核对自定义名称不会被自动标题覆盖。

## 边界

标题是便于找回话题的摘要，不代表相关饮食或训练操作已经保存或生效。
旧消息、滚动摘要、任务状态、工具结果和业务确认机制继续使用原实现。
本轮只在本机和 Android 模拟器验收，真实 iOS、云部署未进行。
