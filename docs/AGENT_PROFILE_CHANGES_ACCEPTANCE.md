# Agent 个人资料修改与验收

日期：2026-10-06。复用现有个人资料服务、测量记录和确认机制；未提交、推送或部署。

## 实现

- 明确修改昵称、性别、出生日期、身高、最新体重、训练经验、每周训练天数、单次训练时长，
  路由为 `profile_update_draft`，不把资料字段和修改指令保存为长期记忆。
  普通稳定偏好仍可自主记忆；记录某日体重、腰围等仍走身体测量任务。
- `read_profile_for_update` 读取当前账户的实际资料、最新体重与版本。
  `propose_profile_update` 必须先读取，再生成 `profile_update` 确认卡，只传明确要求的字段。
  未提出修改的字段省略；清空可选字段需明确要求。体重不能通过资料草稿清空。
- 卡片用中文逐项展示原值与新值，包含单位。待确认不修改资料；缺少真实卡片不声称操作成功。
  性别与训练经验翻译为中文，昵称保持原文，不因内容与枚举值相同而被误译。
  同次工具重复调用复用相同参数的确认卡，普通问答和其他任务不开放资料写草稿工具。
- 确认执行沿用 `ProfileService.update_profile`、事务、行锁、版本和现有审批幂等机制。
  取消、拒绝及旧版本确认不会修改资料；跨账户不能确认。
- 修改最新体重会新增当前测量，保留旧体重记录，不覆盖历史。资料频率/时长变化不会自动修改已有训练计划；
  体重变化不会自动修改营养目标。需要调整计划或目标时应另行提出并审核。
- 进入“我的”页面刷新资料，避免聊天确认后页面继续显示缓存的旧值。历史对话可恢复资料确认卡。
- 根据实际模型回复收紧说明：数值由卡片展示，正文简短说明待确认和影响，
  不从资料频率/时长变化推测训练量、消耗或健康收益。

## 诊断与修复

版本测试复现了已加载 ORM 对象持有旧值的问题：数据库版本更新后，锁定查询可能仍返回请求内的旧对象。
原先旧草稿会通过版本检查。锁定资料时增加 `populate_existing=True`，重新加载数据库值后再校验版本；
复现用例已作为回归测试保留。

## App 验收步骤

1. 先在“我的 → 个人资料”和“训练偏好”查看目前身高、单次训练时长、每周训练频率。
2. AI私人教练发送：“把个人资料里的身高改成175厘米，每周训练天数改成4天，单次训练时长改为35分钟，其他资料保持原样；先给草稿，不修改已有计划、目标或长期记忆。”
   应有一张“修改个人资料”卡，显示每个字段原值与新值。确认前资料页保持原值。
3. 离开后从“历史与记忆”打开原对话，应恢复同一份草稿。点“确认修改”，进入“我的”：
   个人资料显示新身高与单次时长，训练偏好显示每周4次；其他资料、已有计划和目标保持原值。
4. 发送：“请把个人资料的最新体重更新为73.5公斤，先给确认草稿，保留旧体重记录。”
   确认前最新体重不变；确认后个人资料及身体进展读取新测量，原测量仍保留。
5. 另建一份草稿并取消或拒绝，资料应不变。若在资料页手动保存了新值，再确认此前的旧草稿，
   应提示资料版本变化，旧草稿不生效，不覆盖手动修改。

## 限制

- 本轮只补齐上述个人资料字段；正式健身目标、器械/过敏等业务偏好仍走各自已有入口。
  后续已补齐[训练组重量/次数更正与误记组作废](AGENT_WORKOUT_SET_CHANGES_ACCEPTANCE.md)。
- 资料草稿尚不提供逐字段弹窗编辑。需要更正时取消旧草稿，再按正确值生成新草稿。
- 模型服务仍可能超时或返回无效参数；此时应说明失败或需要核对，不能承诺每次表达都成功。
- 最新体重按确认时记录为当前测量；历史某日体重应使用身体记录流程。
- 未配置自启动服务，真实 iOS、云部署及操作系统强制终止后的冷启动不计入本轮验收。
