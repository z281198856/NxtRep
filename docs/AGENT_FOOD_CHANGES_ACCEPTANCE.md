# Agent 自定义食品修改与删除验收

日期：2026-10-06。本轮复用现有食品库、FoodVersion 和确认机制，不提交、推送或部署。

## 实现与保护

- `food_catalog_draft` 支持明确的创建、修改和删除意图，仅开放本次操作需要的工具。
  修改和删除必须先读取当前用户的自定义食品及版本；公共食品和其他账户的食品不能修改。
- `read_custom_food` 按名称、品牌检索。遇到多个同名候选先让用户选择，不任意删除其中一个。
  工具读取失败、版本变化和缺少选择均返回可理解的说明，不能伪装执行成功。
- `propose_custom_food_update` / `propose_custom_food_delete` 生成 `food_update` / `food_delete` 确认卡。
  确认前不改变食品、饮食记录或长期记忆；卡片展示真实食品与影响，修改展示原值和新值。
- 修改只覆盖明确提出的字段，其他值保留。改变基准克重时，未指定的营养按比例换算；
  显式提供的新营养值按新基准使用，不重复换算。估算来源与低可信度不会因确认自动提升。
- 确认修改调用现有版本化更新；确认删除调用现有软删除。旧食品版本及历史餐食营养快照保留。
  新版本出现后，旧草稿无法覆盖它；重复确认仍受幂等和状态检查保护。
- 修改和删除卡可从历史对话恢复。混合请求中部分草稿已生成、另一项待选择时，保留已生成的卡并说明剩余事项。

## 在 App 中验收

1. 在“饮食 → 食品库”创建一个容易辨认的个人食品，例如“验收燕麦饼”，基准100克，热量300千卡。
   如需要检验历史保护，先把它加入一餐，记下该餐热量。
2. AI私人教练发送：“把食品库里我自定义的验收燕麦饼改名为验收燕麦饼新版，每100克热量改为320千卡，其他字段和营养保持原样，先出草稿。”
   应出现修改卡，能核对原值和新值；此时食品库仍是旧名称与300千卡。
3. 点击“确认修改”，重新打开食品库搜索新版名称。应为320千卡，其他营养不变，已保存餐食热量不变。
   回到历史对话应显示已生效状态，不能再次批准旧卡。
4. 发送：“从食品库删除我的验收燕麦饼新版，只删除食品条目，历史午餐要保留。”
   确认前仍能查到食品；核对删除卡后点“确认删除”，食品库不再显示，已有餐食与营养统计保持原值。
5. 可再创建两个同名不同品牌的测试食品，只说“删除食品库里的这个名称”。应要求选择品牌或条目，不直接删除。
   也可以取消或拒绝任意草稿，核对食品不发生变化。

## 限制

- 只修改、删除已经保存且属于当前账户的自定义食品；不编辑公共食品库，也不把此能力等同于修改某餐。
- 修改食品不会回算历史餐食。需要更正旧餐食时仍使用对应的饮食操作。
- 意图理解依赖模型；模型服务波动可能导致明确的失败或重试提示，不保证每次都成功。
- 未完成真实 iOS 验收与云部署，未创建自启动服务。
