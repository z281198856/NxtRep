## 原因与修正

营养追问的路由重放捕获了原始结构化返回：第一次把“碳水应该不超过六十克”规划为修订；经过执行前语义复核后，模型已改成只读查询，但工具调用参数中多出一个闭合括号，形成 `JSONDecodeError: Extra data`。复核阶段没有经过格式恢复，随后切到备用模型并等待约 30 秒超时。旧的模糊删除记录只有校验错误，无法仅凭那份日志断言也是同一个括号错误；本轮一并修正了澄清计划的结构要求并以原长多轮用例复验。

改动在 `backend/src/nxtrep_backend/agents/intent_router.py`：

- DeepSeek 的路由计划使用 JSON 输出模式，附带实际 `AgentIntentPlan` Schema 和格式示例。路由只产出计划数据；业务工具调用仍在原有执行层。其他模型沿用原有结构化工具调用方式。
- 初始规划、写入前语义复核及记忆复核共用格式恢复：无效结构在同一模型最多修正一次，修复失败才走原有失败 / 备用处理。网络超时不被当作格式错误重试。
- 无效返回只作为不可信诊断输入，不由程序猜测或直接执行。所有修正结果继续经过 Pydantic、意图冲突、权限、业务确认和幂等校验。
- SDK 即使部分解析出计划，也要求原始 JSON 完整合法；输出截断、尾部不完整或 Schema 不符均不能执行，避免漏掉原请求中的后续任务。
- 明确澄清计划的合法任务、缺失字段和问题结构，禁止把最近修改过的食物当作模糊删除的默认目标。

采用的 JSON 模式与空白输出边界依据 [DeepSeek 官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。JSON 格式约束不等于语义正确，因此保留本地校验、澄清和确认机制。
