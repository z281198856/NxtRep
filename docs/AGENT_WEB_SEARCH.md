## 联网工具

`search_web(query, domain?, refresh=False)` 已注册为只读工具，覆盖训练、饮食和恢复知识。
通过智谱官方 Web Search API 使用项目已有 GLM 凭据、TLS 和代理配置，不额外安装框架。
每次聊天最多三次搜索，相同关键词及域名在同一请求内复用结果。
后续增加进程内公共搜索缓存：成功结果最多保留15分钟、上限128条，按配置和凭据作用域隔离；失败不进入共享缓存。
结果保留原搜索时间并返回缓存命中/年龄信息；`refresh=True` 跳过请求内和共享缓存，适用于明确要求最新资料的查询，仍遵守每次聊天最多三次实际搜索。
前端已增加可打开的HTTP(S)来源卡。最新验证与设备人工验收步骤见 [本地功能完善与验收](LOCAL_AGENT_NEXT_ROUND.md)。
展示进一步精简：正文不输出查询时间、缓存字段、原始搜索列表和长网址；回复下最多一条小号「来源：网站域名」链接。
历史回复的旧来源附录也在显示时收起，审计数据和原始消息不删除。打开失败时可复制完整链接。

## 何时联网

公开训练、饮食、营养、动作安全和恢复问答默认先检查本地知识：

1. 检索已发布的本地资料，并过滤明显含指令注入的片段。
2. 有片段时，用现有文本模型判断这些片段是否覆盖问题的主要方面，而非用命中数量
   或 RRF 排序分数当作充足性阈值。一条完整资料可以充足，多条重复资料仍可能不足。
3. 无资料、仅部分覆盖、内容矛盾、缺少适用条件或时效不足时，进入联网补充流程。
   此流程会检查是否实际调用了 `search_web`，不能用模型知识冒充联网结果。
4. 本地依据充足时直接使用本地来源回答。明确要求联网或最新数据时保留直接搜索。

自然问句不必包含“联网”。普通问答路径也会检查是否需要公开健身依据；闲聊、
只根据已知数值计算、查询个人记录和业务修改不因为此规则自动搜索。NxtRep 产品功能
依赖项目资料，不能用外部网页推测。品牌记餐继续先查食品库，需要时补充品牌官网依据。

`local_knowledge` 保留本地检索状态、覆盖判断、片段和来源；检索未启用、没有命中、
检索出错与覆盖判断失败分别记录。当前本地配置若未启用 RAG，公开健身知识问题会
按本地依据不可用处理并联网补充；不会声称已经查询了本地资料。

覆盖判断仍依赖模型，不能保证完全准确。判断超时不会被视为资料充分；知识检索任务
可转联网补充。联网失败时保留可用本地依据并说明尚未核验的部分，不重复本地查询。

返回实际来源标题、网址、搜索摘要、查询时间和供应商提供的发布时间。
摘要不等同于已读取完整网页；没有来源、服务繁忙、权限异常、网络失败和超时有各自的
公开错误代码。返回内容及网页指令均为不可信数据，不能覆盖 Agent 规则。
只传入公开查询关键词，不自动提交用户资料、数据库记录或认证信息；账号/令牌模式
会被拒绝。密钥仅用于固定供应商接口的认证，不进入工具结果、用户回复或工具跟踪。

配置项：

```dotenv
NXTREP_WEB_SEARCH_ENABLED=true
NXTREP_WEB_SEARCH_TIMEOUT_SECONDS=15
```

使用已有 `NXTREP_GLM_API_KEY` 和 `NXTREP_GLM_BASE_URL`。关闭搜索或未配置凭据时
工具如实返回不可用。搜索请求使用供应商账户额度，调用次数上限按每次聊天计算。

## 饮食营养口径

食品库没有准确品牌匹配时，可以查询对应地区的品牌官网；查不到时仍可提出明确标注的
估算草稿。搜索结果的网址和份量依据写入草稿备注，确认后才保存。

Agent 自定义条目新增 `nutrient_basis`：

| 值 | 输入的四项营养 | 服务处理 |
| --- | --- | --- |
| `per_basis`（兼容原调用） | `basis_amount_g` 对应的营养 | 按实际克数/基准克数计算 |
| `total_consumed` | 该条实际吃下份量的营养合计 | 将基准克数规范为实际克数，避免再次乘份量 |

新文字草稿优先使用 `total_consumed`。食品库条目仍使用已保存食品版本。
自定义条目保留 `model_estimated/low` 标记；网页参考不等于实际食品已经称重。
API 的正式饮食记录模型保持原样，新增口径只在 Agent 工具入口转换。
