# Agent 多轮任务与确认恢复验收

本轮继续优化既有 Agent，复用确认服务、日历草稿、数据库事务和聊天界面；未部署云端或开展真实 iOS 验收。

## 本轮修复

- 普通追问不再清空待确认卡；新草稿替换时只移除对应旧卡，聊天取消时只移除已核实取消的卡。
- 新增取消未确认草稿工具。仅明确的取消任务可使用，普通知识问答、数据查询不能调用取消；不能批准或撤销已生效记录。引用不明确时应核对选择。
- 改期工具支持替换待确认改期草稿。锁定并核对用户、确认卡版本、原始事件和草稿版本；新日期通过校验并生成新卡后旧卡才失效。新日期冲突或版本变化时不破坏原卡。
- 询问具体草稿是否保存或生效会读取确认状态，而非检索公开知识。根据真实状态明确区分“草稿已保存在待确认区”和“正式记录尚未生效”，不输出英文内部状态或否认已完成的草稿修订。
- 确认按钮处理期间禁用重复决定；同一卡片、同一版本的批准重试复用原幂等键。断网、超时、服务器异常或返回不完整时先核对当前状态，核实成功后展示状态提示；无法核实时保留卡片并说明结果未知。
- 普通回复优先短段落和少量建议，遵守用户简短要求；只引用影响本题的资料，避免复述档案或把通用恢复范围当成个人硬阈值。模型表达仍需用户实际体验评估。

## App 验收步骤

1. 饮食草稿：在 AI 中说“帮我记今天午餐：两个水煮鸡蛋和200克熟米饭，先给草稿”。继续说“米饭改成100克，其他不变”，应出现新卡，原卡不能再批准。
2. 状态追问：接着说“这份草稿还没保存对吗？用两句话解释”。应说明草稿已保存待确认、正式记录尚未生效；确认卡继续显示。点确认后饮食页只增加一餐，营养按新份量计算。
3. 聊天取消：再生成一份待确认晚餐草稿，然后说“取消刚才这份晚餐草稿”。应说明取消结果，卡片消失，饮食页不增加记录；已经确认的午餐不受影响。
4. 改期修订：从月日历选一项未完成训练，要求移到某个空日期、先给草稿；接着要求“刚才的改期草稿改到另一个空日期，原训练不变，先不要执行”。旧卡失效，新卡展示新日期，确认前日历不变，确认后只移动原安排。目标日期已有训练时应说明冲突，不误报成功。
5. 配餐替换：“给一份150克鸡胸肉加100克熟米饭的晚餐搭配，写营养，不要记账”，再说“鸡胸肉换豆腐，蛋白质尽量接近，米饭不变，重新计算”。应保留米饭份量，解释换后份量和营养差异，不生成记账确认卡或增加记录。
6. 简短回答：“一般怎样安排力量训练后的恢复？只说三句话，不要复述我的资料”。检查回答是否直接、简短、保留必要条件；联网来源仍最多一条小号网站链接。
7. 确认断网：在专用测试账户中生成草稿，断开模拟器网络后点确认，再恢复网络并重试同一张卡。应说明暂时无法核实；重新核对或重试后只有一条正式记录。不要为结果未知的操作另建同样草稿。

## 验证边界

- 普通知识问答和配餐建议不会入账；修改正式记录仍须确认。
- 改期替换覆盖已有 shift/merge/skip 草稿；压缩与替代动作草稿尚不支持这套字段编辑。
- 后续草稿恢复轮次已改为依据确认单与版本生成稳定的批准幂等键，跨 App 仓库重建保持一致；后端版本、事务和一次性状态继续阻止重复执行。
- 历史对话自动恢复待确认卡已在后续轮次补齐，状态和验收见 [历史对话草稿恢复](AGENT_DRAFT_RECOVERY_ACCEPTANCE.md)；不将旧消息内容当作当前业务状态。
- 真实模型可能改变表达或选择的估算份量；一次真实测试不保证所有自然问法都稳定。真实照片质量、worker 长时间运行、云部署和真实 iOS 不属于本轮验收。

## 营养追问误判修复（2026-10-06）

后续“AI回复卡住”的时限、食品检索上限和事件流恢复修复，见
[AI回复长时间等待修复](AGENT_STREAM_TIMEOUT_FIX.md)。

实际会话“午饭是泡脚鸡胗饭”生成待确认饮食草稿后，“碳水应该不超过六十克”
被路由成 `memory_write`，没有执行记忆工具，最后返回 `MEMORY_OPERATION_NOT_EXECUTED`。
这属于本餐营养估算的反馈，不应当作长期偏好保存。

- 对具有近期饮食草稿上下文的简短营养反馈，先读取确认草稿、核对份量与合计；明确要求减少份量时才进入草稿修订。长期目标、明确记忆、混合请求和否定修改保留语义路由。
- 草稿状态的简短固定回复只用于明确的状态查询，避免覆盖用户实际请求的营养核对回答。
- 真实 API 回归通过：原草稿68.34克碳水，质疑后读取依据、不改记录；明确减米饭后生成59.889克碳水的新卡，鸡胗仍150克。没有新增长期记忆或正式饮食记录。证据为 `.local/agent-nutrient-followup-live.json`。
- 后端最终全量回归1171通过、17跳过，Ruff通过；Flutter静态分析无问题。Android完整流程通过，包含原话营养追问正常回复、原待确认卡保留、取消及改期确认，没有长期记忆错误提示。临时测试账户已清理。

手动验收：生成一餐草稿后说“碳水应该不超过六十克”，应核对估算、保留原卡，
不报长期记忆修改失败；如需实际调整，可继续说“把米饭减少，让整餐碳水控制在60克以内，
鸡胗不变，先改草稿”。若是已经吃过的餐，应提供真实份量，不为满足上限改写实际进食。
