## 本轮行为

| 范围 | 用户可见行为 | 业务边界 |
| --- | --- | --- |
| A：自然提问与实际记录 | 复合问题保留各项需求；读取已保存资料、目标、身体记录和相关历史；上周/本周按用户时区、周一边界查询 | 数据查询必须有完整工具结果；缺失读取最多重试一次，仍失败则如实说明 |
| B：可靠结果与错误 | 区分超时、连接失败、模型繁忙、数据访问失败、内容不完整、记录不存在、状态冲突和业务校验失败；保留部分成功结果 | 不将超时视为成功，不承诺未知操作未发生；错误和工具跟踪不返回原始密钥、SQL或供应商响应 |
| C：文字饮食记录 | “两个鸡蛋和一碗米饭”可得到估算份量、来源、合计营养和待确认草稿 | 优先查现有食物库；自定义估算标注 `model_estimated/low`，没有网页检索则不声称查过网页；批准后入账 |
| D：训练改期与重量递增 | 改期卡展示日期前后变化；递增卡展示动作、原重量、建议重量、依据和警告 | 读取真实日历和已完成记录；疼痛、异常或信息不足时保守处理或要求复核；批准后修改活动计划，保留历史训练 |

模型客户端复用 HTTPX 的证书配置，继续验证证书和主机名，显式代理通过 HTTPX 客户端传递。
本机此前每次建立工作流重复加载证书，阻塞接口约 34 秒；修复后单独初始化测得首次约 4.3 秒、后续约 2.2 秒。
这些是本机初始化耗时，完整回答仍受模型、检索和网络耗时影响。

## 验证入口

后端在 `backend` 目录执行：

```powershell
$env:RUN_DATABASE_TESTS = '1'
& ./.venv/Scripts/python.exe -m pytest -q
& ./.venv/Scripts/ruff.exe check src tests
```

数据库测试创建独立数据并回滚。覆盖草稿不写正式记录、批准生效、重复批准不重复写入、
改期冲突、未完成训练拒绝递增、疼痛/中断保守处理、计划版本变化及北京时间跨日边界。
常规测试覆盖路由、工具结果缺失/不完整、错误分类、失败审计脱敏、确认卡和模型客户端配置。

真实模型与 Android 验收为显式启用项，需要已有本地 API 和模拟器：

```powershell
$env:RUN_LIVE_AGENT_TESTS = '1'
$env:RUN_AGENT_DEVICE_TESTS = '1'
& ./.venv/Scripts/python.exe -m pytest tests/test_agent_live_acceptance.py -q
```

该验收只创建虚构的临时用户和固定资料，不使用现有用户健康数据；随机账号和登录凭据不打印。
测试结束删除临时用户和 Flutter 定义文件。接口证据及模拟器日志保存在被 Git 忽略的 `.local` 目录。
模拟器流程通过真实聊天流查询当天记录、生成文字饮食卡、点击确认保存，再检查实际饮食条数增加。

Flutter 在 `frontend` 目录串行执行 `flutter test --no-pub` 和 `flutter analyze --no-pub`。
Android 验收用 `integration_test/local_agent_capabilities_smoke_test.dart`，需要真实模型和本地后端，
普通单元测试不执行该文件。

## App 人工检查

1. 在“AI私人教练”输入：“我上周和本周分别训练了几次？今天记录的热量和蛋白质是多少？请查实际记录。”核对训练历史和饮食页。
2. 输入：“帮我记今天午餐：两个水煮鸡蛋和一碗熟米饭，按常见份量估算，先给待确认草稿。”检查份量、估算依据和总量；确认前饮食记录应不增加，确认后增加一条。
3. 输入：“把某日期的训练移到某日期，先给调整草稿。”使用自己日历上的实际日期；核对日期预览，取消时日历不变。
4. 完成并保存训练后输入：“根据我最近一次已完成的训练，给下次保守重量递增草稿。”核对动作、重量和警告；确认前计划不变，确认后活动计划变化，历史记录不变。
