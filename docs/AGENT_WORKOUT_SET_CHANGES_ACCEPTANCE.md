# Agent 训练组更正与作废验收

日期：2026-10-07。接续现有训练记录、确认卡和修订服务。本轮不部署云端、不做真实 iOS、不提交或推送。

## 实现范围

- 聊天更正已保存训练组的实际重量、次数，路由为 `workout_set_update_draft`；
  作废一组误记数据走 `workout_set_void_draft`。修改计划、下次递增和长期记忆分别使用原有任务。
- `read_workout_set_for_change` 按训练日期/真实训练 ID、动作名和组序号读取当前账户的有效组。
  优先精确动作名称；没有唯一候选时要求选择，不猜选最近训练或最后一组。日期读取最多20次训练，超出时要求指定训练。
- 必须先读取版本，再通过 `propose_workout_set_update` 或 `propose_workout_set_void` 生成确认卡。
  更正只含明确要求的重量/次数，未提及的次数、重量、RIR、标签等保持原值。自重可用0公斤；必填数值不能清空。
- 草稿保存不修改正式训练；卡片展示日期、动作、组序号、原值、新值及本次训练量变化。
  同次工具重复调用相同参数复用同一卡。只有真实确认卡才能算提案完成，纯文字不能伪装操作成功。
- 确认后复用 `WorkoutService.update_set/void_set` 和 `WorkoutSetRevision`，保留修改前后值和原因。
  作废组保留数据库记录及修订历史，但不再出现在有效组详情和统计中；其他组及已有训练计划保留。
- 确认同时核对训练和所选组的版本；其他组修改导致整次训练版本变化，也会阻止旧预览生效。
  行锁查询重新加载数据库值，避免请求内已加载对象绕过版本检查。
- 更正/作废后，训练详情、历史组数、训练量及该动作的个人最佳记录按有效数据更新。
  个人纪录重算仅限当前账户、受影响动作；较晚训练的纪录事件可能相应变化，其他动作和用户不受影响。
- 新递增草稿使用更正后的有效组。递增草稿保存来源训练版本，确认时发现来源已改则拒绝旧草稿；
  旧格式草稿以来源修订时间检查，不依据已过期组数据修改未来计划。

## 诊断依据

本轮数据库测试复现：一组从50公斤×10次改为40公斤×7次，另一组45公斤×8次未变。
总训练量已变成640公斤·次，但原服务的个人纪录仍是50公斤/10次。
现已在更正和作废时重算该动作的纪录，修复后为45公斤/8次；后续作废第二组则为40公斤/7次。
复现和跨训练、跨动作、跨账户隔离用例保留为回归测试。

模拟器还发现训练历史列表判断 `finished`，实际接口返回 `completed`，导致正常完成训练显示为“训练已结束”。
本轮修正该状态判断，设备流程同时核对完成状态、组数、训练量和有效组详情。

## App 人工验收

1. 打开“计划 → 训练历史 → 查看全部”，选一场已有重量/次数的训练。
   如果还没有历史记录，先在训练页记录并完成一场训练，再进行以下验收。
   记下实际日期、动作名称、第几组以及原值。以下示例日期和动作必须换成你自己的真实记录。
2. AI私人教练发送：“把2026-10-05那次训练中，传统硬拉第2组的实际重量更正为40公斤、次数更正为8次，其他组和训练计划保持原样，先给草稿。”
   应显示“更正训练组记录”卡及新旧值。确认前，训练详情保持原值；“历史与记忆”不应增加这条修改指令。
3. 点“新对话”，再从“历史与记忆”打开原对话，应恢复同一卡。点“确认更正”，
   重新进入训练历史，所选组应为40公斤×8次，其他组、原训练目标和活动计划保持原样。
4. 发送：“把2026-10-05训练中传统硬拉第2组作废，是误记，保留其他组和修订历史，先给草稿。”
   应显示“作废误记训练组”卡。确认前仍有该组；点“确认作废”后详情只保留其他有效组，组数和训练量减少该组的贡献。
5. 再生成更正草稿，取消或拒绝，训练记录应不变。若仅说“改一下卧推记录”而没确定具体训练/组，
   应要求定位；同一天多个同名组应选择具体训练，不得任意修改。
6. 旧草稿生成后，若同次训练通过现有入口发生更正，再确认旧卡，应说明记录版本变化、旧草稿未生效。
   若先生成递增草稿，再更正其来源训练，旧递增草稿也应被拦截；重新生成才使用最新有效数据。

## 边界与限制

- 本轮仅更正已有组的重量/次数、作废误记组。新增组、恢复作废组、修改动作或组顺序、整次训练删除不在本轮范围。
- 已保存饮食记录的更正/删除由后续一轮补齐，见 [已保存饮食验收](AGENT_SAVED_MEAL_CHANGES_ACCEPTANCE.md)。
  身体测量、正式目标和业务限制的修改不属于本轮训练组范围。
- 卡片尚无逐字段弹窗编辑。值不对时取消旧草稿，按正确数值重新提出。
- 两张针对同次训练的草稿不能作为原子批量更正：确认第一张后训练版本会增长，其他旧卡需重新生成。
- 模型可能超时或未调用正确工具，仍应给出真实失败或待选择状态，不承诺任意表述都成功。
- 修订记录可从现有 `/workouts/{id}/revisions` 接口读取；本轮没有新增修订历史专用页面。
- 本地数据库、后端和模拟器按需启动，worker 不参与此项同步确认；没有创建自启动服务。
