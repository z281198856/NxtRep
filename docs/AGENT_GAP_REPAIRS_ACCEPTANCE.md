# Agent 多轮理解与执行缺口修复验收

完成日期：2026-10-17。本轮针对只读排查确认的六类缺口增量修复，保留现有图主流程、数据库模型、API、业务 Service 和确认机制。

## 已修复的行为

| 问题 | 当前行为 |
| --- | --- |
| 参考餐“追加蒸蛋”变成“替换米饭” | 参考餐工具增加独立 additions 和 remove_item_indices，保留 replacements。未提及食物由程序复制；网关校验本轮所需的新增/替换/移除数量，阻止把追加降级成替换或绕过参考餐工具重建。确认卡与工具结果保留实际操作摘要。 |
| 未确认餐食换菜只改名称或忽略修改 | 待确认草稿支持完整 replacement，也支持 additions/移除。新菜经现有 NutritionService 解析食品版本或估算。仅换名称而不提供完整新食物/营养的危险请求会被拒绝，原卡保持有效。 |
| 选中鸡胸肉却能修改米饭 | 网关核对嵌套变化/删除索引与当前选中项；工具另外核对刚读取的食物项目。明确整餐删除仍可用食物名称查找整餐，餐内选项不会被自动扩大成整餐删除。 |
| 训练只改重量、漏掉组数 | 整动作更正支持 sets，并与 weight_kg/reps 一起进入现有原子确认操作。减少时作废末尾组，增加时创建新组；沿用版本检查、历史和幂等。未支持的实际修改会明确阻断部分草稿；重复返回原日期作为上下文不再误拦截。 |
| 连续任务切换覆盖更早任务 | 保留原 suspended_task 字段并增加小型暂停任务列表，兼容旧JSON状态；可通过真实 resume_task_id 恢复。直接纠正较早暂停任务时也能使用可信实体恢复原任务。歧义时澄清，不猜选。 |
| 不同日期新动作继承旧训练ID | 明确新日期与旧训练日期不同，不继承或重新注入旧 workout_id/session_id。原有动作数字不继承、业务日期和状态校验继续保留。 |

前端确认卡补充了组数变化、新增组和作废组的展示。重量/次数原有展示与确认交互保持兼容。

## 在 App 中验收

先从项目目录运行最新本地版本。需要更新确认卡展示时可使用：

```powershell
.\Start-NxtRep.cmd -RestartBackend -Rebuild
```

无需启动 worker；使用你自己的测试账号操作即可。正式写入仍需你核对并点击确认。

### 1. 复制餐食并追加，原食物不丢失

1. 发送“记录今天晚饭：去皮鸡腿肉150克、炒空心菜150克、熟米饭190克，按常见做法估算。”核对并确认这份源记录。
2. 发送“昨天晚上跟今天晚上一样，不过多加了一碗肉沫蒸蛋”。
3. 新草稿应有四项：鸡腿肉、空心菜、米饭、蒸蛋。日期是昨天；米饭仍是190克。源餐不变。
4. 确认前不应新增正式晚饭；确认后只新增一份目标晚饭，不修改源餐。

### 2. 未确认草稿换菜

1. 在上面的目标草稿尚未确认时发送“这份还没确认的晚饭，蒸蛋换成清炒西兰花，其他不动，没称重按一小碗估算”。
2. 更新后仍为四项；蒸蛋消失，西兰花出现并使用自己的营养估算；米饭、鸡腿肉和空心菜保持原样。
3. 旧卡应关闭，只有新卡可确认；不要求你自己估算热量或脂肪。

### 3. 餐内目标与歧义

1. 对一顿同时有米饭和鸡胸肉的已保存餐发送“刚才那份鸡胸肉改成200克，米饭不动”。
2. 确认卡只显示鸡胸肉份量变化。若随后改为米饭，系统重新读取并选中米饭。
3. 发送“刚才那个删了”且存在多个可能对象时，应询问对象，不自行删除米饭、鸡胸肉或整餐。

### 4. 重量与组数同时纠正

1. 在没有其他正在进行训练的测试环境中发送“记录今天杠铃卧推60公斤，四组，每组8次”，核对后确认。
2. 发送“不对，重量是55公斤，实际只做了三组”。
3. 确认卡应显示4组→3组、保留组变55kg、末尾组作废。确认后训练历史为三组55kg；同一次训练和其他动作不变。
4. 再发送“实际是五组”，确认卡应新增两组；原各组一致时可以沿用55kg和8次。原各组不一致时询问新增组信息。

### 5. 多次任务切换与恢复

1. 发送“帮我记录卧推60公斤”，暂不补组数/次数。
2. 切到另一个尚未完成的任务，例如“帮我记今天午饭”，暂不补食物。
3. 再请求训练计划草稿。
4. 发送“继续刚才还没记完的卧推，四组，每组八次”。应恢复卧推已有60公斤并补入4×8，不能把饮食参数带入训练，也不应重新询问已给出的重量。
5. 有多个同类任务且指代不明确时，应澄清要恢复哪一个。

### 6. 新日期不继承旧训练

结束正在进行的训练后，再发送“再补记昨天的上斜卧推，20公斤，三组每组十次”。应使用昨天的新训练草稿，不把它追加到今天的训练。业务上已有另一场进行中训练时仍需按原规则先结束或明确追加目标。

## 兼容性和限制

- 结构化状态最多保留五个暂停任务。达到上限时返回明确原因并保留已有状态，不静默覆盖。
- 增加训练组且原各组负重或次数不同，必须补充新增组信息；不猜测具体表现。
- 本轮餐食追加覆盖参考餐新建和未确认的新增餐食草稿。对已保存原餐追加新食物尚未扩展成通用编辑接口；缺少对应能力时应阻止不完整草稿，而不是通过替换绕过。
- 对已保存训练真正改日期等未提供业务契约的修改，当前明确阻断部分执行；本轮解决的是新日期任务错误继承旧训练ID。
- 已经确认的历史错误餐食没有自动回填或撤销，包括之前丢失米饭的记录。
- 有限真实模型样本通过不代表所有自然表达均已覆盖；本轮反例已转为回归保护。
