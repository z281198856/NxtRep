# 账户安全管理验收

日期：2026-11-01（Asia/Shanghai）。本轮范围为修改密码与登录设备管理。保留已有未提交改动，未提交、推送或部署。

## 用户入口与行为

入口为“我的 → 账户安全”。

- 修改密码：填写当前密码、新密码和确认新密码；支持显示 / 隐藏密码，校验 8–128 个字符、两次输入一致且新旧密码不同。成功后更新本机令牌，其他旧登录失效，当前设备继续使用。
- 登录设备：展示设备名称、首次登录时间和最近验证时间。当前设备由服务端标记，不按名称推测；同一设备多次独立登录可能显示多条记录。
- 退出设备：其他会话支持逐台退出，均需确认；“退出其他所有设备”保留当前会话。当前设备不提供误触式的单设备退出按钮，退出当前账户沿用“我的 → 退出登录”。
- 被远程退出：后续请求和刷新均拒绝，App 清理本地登录状态，关闭已打开的受保护页面并回到登录页。
- 密码修改结果不明确：网络超时、异常响应或安全存储失败时，不自动重复修改，提示重新登录核对。已确认修改成功但令牌保存失败时，明确提示使用新密码登录。

## 后端与客户端补强

- 新的访问令牌绑定真实登录会话，每次鉴权检查会话归属、撤销和过期状态，避免仅停止续期但仍可使用旧访问令牌。
- 刷新令牌仍一次性轮换，保留同一会话 ID 和首次登录时间，避免续期不断生成新设备记录。旧刷新令牌再次使用被拒绝。
- 升级前没有会话绑定的访问令牌返回 `INVALID_ACCESS_TOKEN`；有效的旧刷新令牌可自动换取新版凭证。无效旧凭证不继续放行。
- 新增 `POST /auth/sessions/revoke-others`；设备列表新增服务端计算的 `is_current`。
- 修改密码的当前密码错误次数持久化，连续五次错误临时锁定 15 分钟；修改成功重置失败次数。
- 客户端串行处理密码修改、令牌刷新、登录与退出，避免旧刷新结果覆盖新密码对应的登录凭证。
- `INVALID_CURRENT_PASSWORD` 不被当作访问令牌过期而自动刷新、重复提交。
- 会话结束时清理导航栈，避免登录页背后仍保留安全页面。正常退出在网络失败时仍清理本机登录。
- 未引入新的客户端依赖或数据库表迁移，继续使用既有安全令牌存储。

实际数据库场景验证：同一设备续期保留原 ID；旧刷新令牌不能重用；退出其他设备后其访问与续期均失败；当前设备保持有效；跨账号不能撤销对方登录；修改密码使旧密码、旧登录及旧刷新令牌失效；并发续期不能复活已退出的设备；错误密码次数及锁定在真实数据库中持久化。

Android 用例使用临时账号与内存令牌存储，实际执行：从“我的”进入安全页面，取消并确认逐台退出，退出其他所有设备，输错当前密码后继续保持登录，成功修改密码后继续使用，以及另一登录撤销当前设备时关闭已打开的修改密码页面并返回登录。临时账号和本地测试凭据文件自动删除，未修改真实用户密码或撤销真实用户会话。

## 全量后端回归边界

扩大回归使用项目内独立临时目录后，结果为 2111 项通过、62 项跳过、12 项失败，无临时目录权限错误。其中一项是接口文档遗漏；已补齐本轮安全接口及已有餐食 / 饮水接口，后续接口契约与账户相关 63 项复验通过。

另外 11 项失败集中在既有 Agent 来源展示、餐食改期和过期草稿恢复用例。使用本轮修改前的源码副本对照，相同 11 项均失败（该组 91 项通过）。本轮未修改这些业务逻辑，未将它们计为通过，也未扩大账户安全范围修复它们。

因此，“账户安全相关测试通过”不等同于“整个后端全量测试通过”。失败明细与基线对照保留在 `.local/account-security-preexisting-failures.json`。
