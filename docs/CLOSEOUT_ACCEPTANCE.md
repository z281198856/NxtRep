## 验收发现与处理

1. **营养核对被误当成修改草稿。**完整聊天设备用例中，“碳水应该不超过六十克”被规划为餐食修订，执行失败并显示修订未完成。现在在现有执行前校验中发现此类只读核对与写计划冲突后，要求模型有界复核；再次提出冲突计划则拒绝执行。明确减少米饭、重估少油做法等真实修改仍交由原有语义规划与确认机制处理。新增测试覆盖纠正为查询与重复错误计划被拒绝，两者都在执行任何业务写入之前发生。
2. **待确认训练调整使用完成语气。**人工查看真实回复发现“已按要求压缩”等表述，容易与尚未批准的调整卡混淆。合成规则补充要求用建议方案的语气描述改期、时长和训练量；真实验收增加完成语气检查，并在批准前核对原日历日期、时长与动作快照均未变。
3. **旧设备脚本未滚动查找饮食入口。**饮食页新增内容后，拍照与手动填写入口可能位于首屏以下，懒构建列表中尚不存在对应 Widget。设备用例现先在饮食页滚动查找，保存后再滚回真实餐食记录；保留了照片入口、实际保存及导航断言。
4. **验收环境及格式问题。**第一次复测的临时账户缺少目标与限制，导致资料页不能完整加载；补齐临时资料后原显示名断言通过。整理了三个既有后端测试文件的长行。新增日历检查曾误引用不存在的 `version` 字段，已改为比较实际日期、时长和动作快照。上述初始失败日志均保留。

## 初轮未解决问题（现已后续复验通过）

1. **P1：模糊删除没有稳定转为澄清。**真实多轮模型对“把刚才那个删了”的计划重复未通过校验，返回 HTTP 502 / `AGENT_RESULT_INVALID`，而验收要求先询问删除整餐还是餐内食物。最终六项真实测试中，此用例仍失败。校验阻止了误删，但正常追问体验不合格，仍需定位内部计划冲突或结构化解析的具体原因。
2. **P1：复杂会话中的营养核对仍可能超时。**原始误判已有保护，独立真实接口专项验证能读取原草稿并在明确请求后修订；完整设备对话的第二次复验却在同一追问发生 `AGENT_TIMEOUT`（路由阶段约 33.6 秒，没有业务工具执行）。它与模型调用并发或服务延迟的关联尚未证实，不能直接归因于网络或认定修复完成。

第一次真实多轮曾通过，后续最终轮次仍失败；本记录保留全部轮次，并以最终失败作为未通过依据。下一轮应优先处理以上两项，并在不减少业务断言的情况下通过独立接口与完整设备对话验收。
