# NxtRep 精简用户体验规范

> 本文约束前端信息架构和用户流程。后端可以保留完整能力，但不得把技术复杂度直接暴露给普通用户。

## 1. 产品骨架

底部固定五个入口：

1. **首页**：今天练什么、开始/继续训练、快速记录。
2. **计划**：当前计划、日历、历史、动作库。
3. **进展**：训练表现、体重围度、饮食和报告。
4. **AI 教练**：聊天、发照片、建议和待确认修改。
5. **我的**：账号、资料、提醒、隐私、导出和删除。

不提供社区、关注、排行榜、搭子匹配、动态或公开模板分享。

## 2. 首次使用

只询问四项：主要目标、每周训练次数、地点/器械、是否存在伤病或疼痛。
选择“没有伤病”后立即继续，不要求填写空白伤病记录。年龄、身高、体重、经验、
训练时长、动作偏好和饮食限制都在实际需要时再补充，并且允许跳过。

## 3. 训练主流程

`今日训练 → 开始训练 → 记录重量/次数 → 完成一组 → 自动休息计时 → 完成训练`

- 开始训练后自动显示有效训练总时长。
- 暂停训练时停止累计；继续后恢复。
- 完成一组后按动作默认值启动休息倒计时。
- 休息计时提供跳过、暂停/继续、`+15 秒`、`+30 秒`。
- App 进入后台、被关闭或离线后，计时根据时间戳恢复，不依赖服务器逐秒计时。
- 默认只展示重量、次数和完成按钮；RIR/RPE、标签、备注放在展开区。
- 训练前状态和训练后反馈均可跳过。
- 跳过、替换、添加动作放在动作菜单中。

## 4. 自动离线同步

- 用户的每组记录先写入本机，联网后后台自动同步。
- 正常情况下不显示“同步中心”、版本号、队列或冲突记录。
- 客户端生成稳定记录 ID，重复上传由服务端幂等去重。
- 能安全合并时自动合并；不能安全合并时保留本地副本并重试。
- 只有持续失败才使用普通语言提示：“同步未完成，记录仍保存在本机”。
- 用户不需要决定“使用客户端版本还是服务器版本”。内部诊断接口仍保留给开发排错。

## 5. AI 教练最小必要能力

用户只面对一个 AI 教练，不选择训练 Agent、饮食 Agent 或身体 Agent。必须保留：

- 读取用户已授权的训练、饮食、身体和目标数据。
- 回答问题、解释趋势、给出训练与饮食建议。
- 生成训练计划、调整方案或记录草稿。
- 以轻量确认卡让用户批准会改变正式数据的操作。
- 记住经用户同意的长期偏好和限制。
- 接收和分析照片。

会话分支、Agent Run、工具调用、RAG、Memory 版本和失败重试都属于内部实现，
不得成为普通用户必须理解或操作的页面。

## 6. 照片分析

照片能力不是被精简掉的高级功能，而是 AI 教练的必要输入方式：

- **食物照片**：识别食物，给出份量、热量和宏量营养区间，用户确认后记录。
- **身体照片**：描述可观察变化、给出不确定性，不输出伪精确体脂率或医疗结论。
- **前后对比**：在授权照片间比较可观察趋势。
- **计划截图**：识别训练日、动作、组数和次数，生成可校对草稿。
- **混合图片**：系统自动判断用途；必要时只追问一个最关键的问题。

统一流程是 `拍照/选图 → 查看分析 → 必要时确认保存`。图片分类、模型路由、
置信度计算和多分支执行不直接显示。

## 7. 确认与高级功能

用户直接填写表单或点击完成时立即保存。只有以下情况需要确认：

- AI 修改训练计划、目标、日历或已有正式记录。
- AI 将识别结果保存为正式记录。
- 删除重要数据或执行不可逆操作。

确认卡首屏只显示操作、主要影响和确认/取消，详细差异按需展开。高级报告、
主动提醒分类、Memory 管理、多会话管理、审计和同步诊断全部放入二级入口。
