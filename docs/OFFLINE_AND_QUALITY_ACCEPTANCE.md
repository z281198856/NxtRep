# 离线记录、草稿恢复与持续质量验证

本轮日期：2026-11-02（Asia/Shanghai）。代码保留原有未提交改动；本轮未提交、推送或部署。

## 使用方式

入口为「我的 → 离线记录与草稿」。离线或有待同步记录时，主页面顶部也会出现入口。

- 手动饮食、食品记录、核对后保存的餐食照片、饮水、身体测量，以及已开始训练的记组，先写入本机，再尝试提交。没有网络时明确显示「已保存在本机，待同步」。待同步项不计入服务端统计。
- 已开始训练会缓存当前训练；断网及重启后，待同步组叠加在训练页面并标记「待同步」，继续记组时沿用递增组次。
- 应用在前台约每 30 秒、回到前台时尝试同步，也可以点击「立即同步」。登录状态失效时先重新登录；版本冲突、记录已结束等情况保留内容，停止自动重试，供用户核对。
- 新训练的开始、训练的结束、旧记录修改和删除、设置变更、AI 确认卡执行需要联网。训练有未处理的待同步组时，先处理这些组，再修改或结束训练。
- 草稿包括手动饮食、饮水、身体测量、训练组、AI 文字输入、餐食照片和说明、照片识别预览及手动修改值。再次打开原表单会恢复；草稿列表可继续填写或删除。训练组草稿先返回首页，再打开对应训练和动作。
- 照片草稿恢复不会自动上传、识别或写入饮食。AI 发送中断保留文字，并在再次发送前提示核对上次聊天结果。聊天图片附件、身体照片、训练计划导入等其他录入流程不在本轮持久草稿范围内。
- 本机内容用平台安全存储保存，按服务器地址与账户 ID 分开。退出登录会隐藏本机记录，同一账户再次登录后恢复；卸载或清除应用数据会丢失未同步内容。

## 一致性与恢复边界

每条记录先持久保存原始发生时间、请求内容及同一个防重复标识，随后才发请求。连接超时、服务端繁忙或成功响应不完整时，保留待同步项并复用标识。已进入队列的表单不会在重启后再次作为未提交草稿恢复。

服务端通用防重复标识的保留期为 24 小时。客户端对曾尝试提交、距离第一次尝试已达 23 小时的记录停止自动重试并提示核对，防止过期后重复写入。一直没有发出请求的纯离线记录可以在多天后首次同步。此机制优先保留内容，无法自动判断的旧提交需要用户核对。

同步时不持有草稿写入锁，避免慢请求阻塞输入保存；账户切换会停止原账户的后续发送。训练组接口增加 `client_generated_id`，让客户端能识别「服务端已写入、上次响应丢失」的同一组，避免页面重复叠加。

离线启动仅恢复本机曾成功登录且仍保留登录凭据的账户缓存。它不证明服务器会话仍有效；联网后会重新核实，鉴权失败不会使用缓存绕过账户安全管理。

## 持续质量验证

在项目根目录运行：

```powershell
# 固定回归、全部 Flutter 测试和静态检查，不调用模型。
.\backend\.venv\Scripts\python.exe .\scripts\verify_quality.py

# 增加临时账户的真实数据库和 AI / 非食物图片检查。
.\backend\.venv\Scripts\python.exe .\scripts\verify_quality.py --database --live --repeats 2

# 指定明确同意用于验收的餐图、实际称重及参考营养；会上传至已配置的视觉服务。
.\backend\.venv\Scripts\python.exe .\scripts\verify_quality.py --live --samples C:\path\meal_samples.json --repeats 2

# 与上次报告比较失败项。
.\backend\.venv\Scripts\python.exe .\scripts\verify_quality.py --baseline .\.local\quality-runs\previous-run\report.json
```

每次运行独立输出到 `.local/quality-runs/<UTC时间-随机标识>/`，包括 JSON / Markdown 报告、测试日志、JUnit 结果、真实模型检查明细、来源代码及测试集指纹。失败返回非零退出码，可接入后续本地检查或 CI；本轮没有创建定时任务或云端工作流。

固定回归覆盖多轮澄清、更正和过期确认卡、来源展示、拍照失败与超时、营养计算、前端恢复。原先 9 个依赖当前月份的测试固定到对应样例的时间；2 个旧来源测试更新为「回答选用来源才展示」，增加未选用来源不附链的检查。

真实模型验收使用临时账户：验证训练容量和热身组说明、同一请求返回同一运行结果、待确认餐食从 100 克更正到 150 克、没有直接写入正式记录，以及非食物图片不能编造餐食。测试结束清理临时账户和上传图片，不提交个人身体照片。

餐图样例格式见 [meal_samples.example.json](quality/meal_samples.example.json)。示例数字仅说明格式，必须替换成该照片的实际称重及有依据的热量参考，不能当成已有真实样本。`amount_g` 和 `kcal` 可独立提供；未提供的真值不计算相应准确率。菜名按人工列出的别名匹配，每个检测只能匹配一项，分别检查菜名召回、额外食物、份量相对误差、热量相对误差及份量区间覆盖率。默认 35% 是可调整的验收阈值，不代表已经达到这一准确率。
