# 历史对话草稿恢复与验收

本轮仅补齐历史对话中的待确认草稿恢复；不增加食品修改/删除，不提交、推送或部署。

## 原因与实现

- 原先 `openConversation` 只读取文字消息，然后清空确认卡。后端草稿仍存在，但回到聊天不能继续操作。
- 新增 `GET /api/v1/agent/conversations/{conversation_id}/confirmations`，先校验会话归属，再从已持久化的 AgentRun 确定关联的确认单。状态、版本和内容以 Confirmation 当前值为准。
- 追踪 `replaces_confirmation_id` 的替换链，支持份量弹窗产生、没有新 AgentRun 的修订。多次调整后只显示最后的有效草稿；不恢复被替换的旧卡。
- 返回 `confirmation_cards`（仅有效 pending）与 `resolved_counts`（succeeded/rejected/cancelled/expired/failed）。前端显示自然中文状态提示，旧消息中的“待确认”不覆盖真实结果。
- 恢复训练计划、日历调整、递增和营养目标卡的数据库预览；饮食和食品卡复用确认单中的份量、营养与估算说明。
- 同一确认单和版本使用稳定的审批幂等键，App 重新创建仓库后保持相同；后端仍通过现有幂等记录、事务、行锁和版本校验执行。
- 恢复接口失败或数据不完整时，保留聊天历史，明确提示“草稿状态暂时无法核实”，不使用缓存猜测成功或重新生成草稿。可重新打开对话重试。
- 异步恢复期间切换至新对话，不允许旧请求返回后覆盖当前对话。

## App 验收步骤

1. AI私人教练输入“帮我记今天午餐：200克熟米饭和两个水煮鸡蛋，先出草稿”，不确认。进入历史对话，再打开该对话，应恢复待确认卡；饮食页尚无新记录。
2. 点“调整份量”，把米饭改成100克。离开再进入，应显示修改后的克数与营养，仅新卡有效。
3. 关闭并重启 App，进入历史对话，继续操作同一份草稿。确认保存后，饮食页只新增一餐；再次进入聊天只有核实后的状态提示，不再显示该卡的保存按钮。
4. 新建自定义食品草稿，离开再进入，仍有“确认添加”及估算说明。批准后可在食品库查到，饮食页不新增记录。
5. 取消一份草稿后再进入，不应恢复该卡。超过有效期的草稿也不再可确认；通常有效期24小时，不需要为了验收一直等待。
6. 确认时网络中断，恢复后重新进入对话。已成功则显示生效状态；尚待确认则恢复同一张卡。无法核实时明确报错，不伪装保存成功。

## 边界

- 恢复依赖该会话中已保存的运行结果或明确替换链；独立业务页面创建、未关联聊天的草稿不混入历史聊天。
- 不根据旧聊天文字推断或重建确认单，也不自动批准。
- 原有消息读取上限仍为100条，本轮不增加历史消息分页。
- 恢复时读取最新状态；另一个设备随后修改草稿，仍由现有审批版本校验和冲突核实处理。
- Android 控制器重建验收与操作系统强制终止后的冷启动分别记录；真实 iOS 和云部署继续暂缓。
