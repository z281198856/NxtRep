# AI 回复文案与已保存记录展示（2026-10-18）

## 本轮行为

- 普通回复直接说食物、训练内容、估算或调整依据，不说“草稿已创建/已保存/准备好/等你确认”。
- 日常记录正文不复述默认日期、钟点、时间戳、餐次字段和版本。用户主动询问时间、状态或存在真实歧义时，仍准确回答。
- 食品库未收录不作为普通饮食回复的解释；保留份量假设、营养估计与做法/用油造成的不确定性。
- 未确认的提案仍须通过原确认卡执行，不把文案简化变成自动保存，也不伪装执行成功。
- 保存成功后保留原卡内容，以“已保存/已更新/已启用”等状态展示，移除确认、取消、调整份量按钮。
- 重新打开会话时，从真实已成功确认命令恢复展示卡，不从旧 AI 文字判断成功。
- 尚未核实的保存结果不显示成功；同一张已保存卡及其旧回调不能再执行保存。

## 实现范围

复用原有 Prompt、回复合成器、任务快捷回答、确认表、会话恢复接口和 Flutter 确认卡。
没有新建数据库表、修改确认执行逻辑或重写 Agent。

- `agents/prompts.py`、`agents/synthesis.py`：更新普通回复规则；为文字记餐保留浅层营养合计，避免裁剪后重新估算。
- `agents/nodes.py`、`services/agent_handlers/task_action.py`、`meal_date_change.py`：清理直接回答里的流程文案，保留原多轮快捷路径。
- 会话恢复接口增加可选的 `completed_cards`，原 `confirmation_cards` 继续只包含可操作的待确认项。
- Flutter 单独维护已完成展示卡，按卡片原有顺序呈现；会话切换隔离迟到的确认结果。
- 已保存卡展示当时确认的内容快照，饮食/训练等业务页面仍显示最新业务数据。

旧聊天正文保留原始内容，不批量重写历史消息；新生成的回复使用新规则。

## 用户验收步骤

1. 在 AI 新对话发送“午饭吃了米饭200克、鸡胸肉150克，帮我记录”。正文应说营养与估算依据，不重复草稿/确认流程、默认钟点或食品库匹配情况。
2. 核对卡片后点“确认保存”。卡片的食物、份量和营养仍在，状态变为“已保存”，三个操作按钮消失。
3. 从历史重新打开这段对话。已保存卡应仍以只读形式显示，不重新出现确认按钮；饮食页只增加一次记录。
4. 问“这条记录保存了吗”或具体询问记录时间时，AI 仍应回答真实状态或时间，不回避必要信息。

真实 iOS 和云部署未进行；真实模型属于抽样验证，不保证每次措辞完全一致。
