# Agent 回复完成与断流恢复修复（2026-10-18）

## 现象与证据

用户看到模拟器中的 AI 界面停在“正在组织回复”，文字尚未显示完整，输入框处于发送中。
检查时 Android、ADB 正常响应，没有找到 ANR 或应用崩溃，Windows 也没有 CPU 或内存耗尽。
原请求在北京时间 09:53:29 开始、09:53:40 完成，后端状态为 `succeeded`，耗时约 11.16 秒；
293 字回复已经保存，饮食草稿仍为 `pending`，没有执行确认。

这说明服务端已完成与界面结束等待之间存在缺口。当前保留日志不足以确定原生运行时
为何停在当时那一帧，不能声称复现了整个原生冻结。代码与回归测试确认了以下可修复问题：

- 收到完成事件后，仍无期限等待逐字显示缓冲排空。
- 完成后的历史同步没有控制器层面的等待上限，也可能把已收到的成功结果变成错误提示。
- 已知运行 ID、SSE 连接保持打开却不再发事件时，缺少及时查询已有结果的恢复路径。

## 本轮修改

保留现有 API、后端 Agent、业务 Service、数据库、逐字显示和用户确认机制。
只增强 `frontend/lib/features/agent/presentation/agent_controller.dart` 的结果收尾与恢复：

1. 完成事件先解析确认卡；正常文字继续原来的显示节奏。
2. 文字缓冲收尾最多等待 12 秒，之后显示剩余已收到文字，不丢弃内容。
3. 历史与运行恢复查询每次最多等待 8 秒。已收到有效完成结果时，历史同步失败不会撤销该结果。
4. 连续 12 秒没有新的 Agent 事件时，查询已有 `run_id`。只有当前轮、当前对话、对应运行
   的终态结果才恢复；查询期间有新进度则丢弃过时的状态读取。
5. 运行仍进行中、查不到结果或查询失败时，不伪装成功，也不自动重发用户请求。
   原有网络进度超时与手动核实机制继续保留。
6. 结束或退出时取消恢复计时器；已开始输出文字后，节点提示不再退回“正在组织回复”。

恢复使用只读运行查询，不自动批准确认卡，不重复执行记餐。

## 用户复测方法

1. 打开 AI 私人教练，通过“历史与记忆”进入原对话；检查完整回复、原待确认午饭卡和输入框。
2. 发送一条新的知识提问，例如“卧推时怎么保持肩膀稳定？”。回复结束后应能继续输入下一条。
3. 需要新增饮食时再发送新的记餐请求；草稿应可见，确认前饮食页不新增正式记录。
4. 网络中断且结果不明时，使用“核实上次结果”，核实已有请求后再决定下一步。

尚未覆盖真实 iOS、云端部署以及所有原生/系统层面的冻结故障。
